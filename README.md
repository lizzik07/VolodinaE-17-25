# Визуализатор графа зависимостей npm

Конфигурационное управление, ИКБО-17-25, вариант №6.
Сборник практических работ №2, страницы 23–25; общие правила — страницы 4–7.
Выполнила: Володина Елизавета.

Программа получает метаданные напрямую из npm-реестра, выбирает версии
зависимостей, выполняет рекурсивный BFS и выводит описание графа Graphviz.
Готовые менеджеры пакетов и сторонние библиотеки получения зависимостей
внутри программы не используются. Нужен Python 3.9 или новее.
Внешние Python-библиотеки и сборка не требуются.

## Установка, запуск и тесты

После клонирования выбрать ветку сдачи:

```sh
git switch codex/pract3-compliant
./run.sh --package A --test-file tests/fixtures/repository.json --depth 3
python3 -m unittest discover -s tests -v
```

Для Windows или запуска без оболочки:

```sh
python3 src/main.py --package A --test-file tests/fixtures/repository.json
```

Скрипт запуска находит src независимо от текущей папки. Относительный путь
тестового файла считается от текущей папки пользователя. Вспомогательная
проверка PEP 8 (не зависимость программы):

```sh
python3 -m pip install pycodestyle
python3 -m pycodestyle --config=/dev/null --ignore= --max-line-length=79 src tests
```

## Параметры

| Опция | Назначение | По умолчанию |
|---|---|---|
| `--package` | Исходный npm-пакет или имя в тестовом графе; обязательно | — |
| `--version` | Версия или тег исходного npm-пакета | latest |
| `--url` | HTTP(S)-адрес npm-совместимого реестра | https://registry.npmjs.org |
| `--test-file` | JSON-файл; его наличие включает тестовый режим | — |
| `--depth` | Максимальное число переходов от корня; 0–100 | 3 |
| `--reverse` | Вывести обратные зависимости | выключен |
| `--candidates` | Область обратного поиска в сетевом режиме | — |
| `--dot-only` | Вывести чистый DOT без конфигурации и списков | выключен |

`--candidates` и `--dot-only` — вспомогательные опции реализации.
В тестовом режиме URL и версия не используются для получения данных.
Пустой `dependencies` означает отсутствие прямых зависимостей.
Ошибка HTTP не подменяется пустым списком. Тайм-аут одной попытки — 20 секунд, до трёх попыток при сетевой ошибке.
Коды возврата: 0 — успех, 1 — ошибка источника данных, 2 — ошибка опций.

## Этап 1. Конфигурация и ошибки

Вывод настроек имеет формат ключ-значение. Проверяются пустые значения,
имена, версия/тег, адрес и порт, целая неотрицательная глубина и её предел.
Файл проверяется при загрузке: доступность, синтаксис JSON, структура,
имена и наличие всех упомянутых вершин. В сетевом режиме проверяются ответы
реестра и наличие подходящей версии.

Примеры ошибок для демонстрации:

```sh
./run.sh
./run.sh --package ''
./run.sh --package A --depth -1
./run.sh --package A --depth text
./run.sh --package A --depth 101
./run.sh --package A --version ''
./run.sh --package A --url wrong
./run.sh --package A --url http://example.org:wrong
./run.sh --package A --test-file missing.json
./run.sh --package A --test-file ''
./run.sh --package B --test-file tests/fixtures/isolated.json
./run.sh --package definitely-missing-ikbo17-2026 --depth 1
```

## Этап 2. Получение прямых зависимостей

```sh
./run.sh --package is-odd --version 3.0.1 --depth 1
```

Ожидается связь is-odd@3.0.1 → is-number@6.0.0.
Читается JSON метаданных реестра и поле dependencies выбранной версии.
Метаданные кэшируются по имени пакета. Вершины различаются по имени
и версии: несколько версий одной библиотеки не объединяются.

Версии выбираются собственным кодом по точным значениям, тегам, caret (^),
tilde (~), частичным версиям, wildcard (x/*), сравнениям, AND, OR (||)
и hyphen-диапазонам. Учитываются prerelease и npm aliases.
Это анализ обычных registry-зависимостей dependencies; ссылки git/file/URL
вызывают явную ошибку, а не подменяются latest. Отдельные правила установки
peerDependencies, optionalDependencies, overrides, workspace и lock-файлы
не моделируются. Программа не устанавливает пакеты.

## Этап 3. Обход в ширину и тестовый режим

```sh
./run.sh --package A --test-file tests/fixtures/repository.json --depth 3
./run.sh --package A --test-file tests/fixtures/cycle.json --depth 10
./run.sh --package A --test-file tests/fixtures/diamond.json --depth 2
./run.sh --package A --test-file tests/fixtures/isolated.json --depth 3
```

Формат тестового репозитория — JSON-объект:

```json
{"A": ["B", "C"], "B": ["C"], "C": []}
```

Имена — большие латинские буквы; каждая упомянутая вершина должна быть
объявлена. Порядок вывода стабилен, повторы зависимостей удаляются.

За один вызов BFS обрабатывается весь текущий уровень. Рекурсивный вызов
получает весь следующий уровень. Уже добавленные в граф вершины повторно
не обрабатываются, поэтому цикл не приводит к бесконечному обходу.
Глубина 0 показывает только корень; глубина 1 — непосредственных соседей.
Вершины на границе присутствуют, но их исходящие связи не исследуются.
Поэтому пустой список на границе не доказывает отсутствие зависимостей.

Без сортировки и сети BFS занимает O(V + E); стабильный вывод добавляет
затраты на сортировку уровней и списков зависимостей. Память графа O(V + E).
Глубина ограничена 100 для безопасного использования рекурсии Python.

## Этап 4. Обратные зависимости

```sh
./run.sh --package F --test-file tests/fixtures/repository.json --reverse --depth 1
./run.sh --package F --test-file tests/fixtures/repository.json --reverse --depth 3
./run.sh --package A --test-file tests/fixtures/cycle.json --reverse --depth 10
./run.sh --package A --test-file tests/fixtures/isolated.json --reverse
```

Для F на глубине 1 находятся D и E, на глубине 3 — A, B, C, D, E.
Рёбра полного тестового репозитория разворачиваются, после чего применяется
тот же рекурсивный BFS. Сам целевой пакет не включается в список потребителей.

Метаданные отдельного npm-пакета не содержат полный список его потребителей.
Поэтому сетевой обратный поиск выполняется среди явно заданных кандидатов:

```sh
./run.sh --package is-number --version 6.0.0 --reverse --candidates is-odd
```

Кандидаты запрашиваются по latest, цель — по --version; сравниваются
конкретные версии. Этот режим не заявляет поиск по всему npm-реестру.
Обязательные демонстрации обратного поиска выполняются на полном учебном JSON.

## Этап 5. Graphviz и сравнение

```sh
./run.sh --package is-odd --version 3.0.1 --depth 5 --dot-only
./run.sh --package is-even --version 1.0.0 --depth 5 --dot-only
./run.sh --package is-number --version 7.0.0 --depth 5 --dot-only
```

DOT выводится на экран. Все вершины объявляются явно, включая изолированные.
При обратном поиске стрелки DOT сохраняют исходный смысл:
потребитель → зависимость. Вариант №6 не требует сохранять PNG или SVG.
Для демонстрации можно отдельно использовать установленный Graphviz:

```sh
./run.sh --package is-even --version 1.0.0 --depth 5 --dot-only > graph.dot
dot -Tsvg graph.dot -o graph.svg
```

Три текстовых примера и независимое сравнение с npm ls находятся
в [examples/README.md](examples/README.md). npm использовался только
для проверки результатов, не для реализации получения зависимостей.

## Модули и функции

| Модуль | Функции и назначение |
|---|---|
| config.py | nonempty — непустое значение; depth_value — глубина; validate_names — имена, версия, URL; parse_args — разбор опций; print_config — настройки |
| repository.py | request_json — HTTP JSON; load_test_graph — учебный граф; alias_target — npm alias |
| NpmRepository | __init__ — кэши; resolve — выбор версии и вершины; dependencies — прямые зависимости версии |
| graph.py | bfs_recursive — обход по уровням; reverse_graph — разворот рёбер; candidate_graph — область обратного npm-поиска |
| visualization.py | generate_graphviz — DOT с исходным направлением стрелок |
| main.py | build_graph — источник и обход; print_result — результат; main — запуск и обработка ошибок |
| semver.py | version_key — порядок SemVer; partial — частичная версия; format_core — строка версии; upper_bound — верхняя граница; compatible_upper — caret/tilde |
| semver.py | compare — оператор сравнения; token_matches — одно условие; hyphen_matches — диапазон с дефисом; prerelease_allowed — разрешение prerelease; satisfies — весь диапазон; select_version — выбор версии |

Тестовые методы описаны docstring в tests/. Тесты покрывают конфигурацию,
диапазоны версий, кэш, прямой и обратный BFS, циклы, общую зависимость,
глубину, ошибки JSON/файла/сети, изолированные вершины и DOT.

## Структура и история

В корне находятся README.md, .gitignore, run.sh, src/ и tests/.
В репозитории отсутствуют архивы, бинарные файлы, кэши Python, настройки
редакторов и результаты сборки. Примеры DOT и штатного вывода — текстовые
материалы демонстрации, предусмотренной этапом 5.

Ветка codex/pract3-compliant подготовлена как отдельная последовательная
пересборка работы: пять коммитов с работающими состояниями этапов 1–5 и отдельная проверка стиля.
Это новая история доработки, а не восстановленные задним числом старые этапы.
Коммиты имеют формат Conventional/Scoped Commits; описания — на русском.
Исходная ветка main и предыдущие практические работы сохранены отдельно.
