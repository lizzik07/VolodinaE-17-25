# Визуализатор графа зависимостей npm

Конфигурационное управление, ИКБО-17-25, вариант №6.
Выполнила: Володина Елизавета.

## Описание

Программа получает зависимости npm-пакетов напрямую из реестра по HTTP,
строит граф рекурсивным обходом в ширину (BFS) и выводит его на языке Graphviz.
Готовые менеджеры пакетов и сторонние библиотеки получения зависимостей
в реализации не используются. Для проверки без сети предусмотрен JSON-файл
тестового репозитория с именами пакетов из больших латинских букв.

## Требования и запуск

Python 3.9 или новее, только стандартная библиотека. Сборка не требуется.
Из корня репозитория:

```sh
./run.sh --package is-odd --version 3.0.1 --depth 3
```

Без shell-скрипта:

```sh
python3 src/main.py --package A --test-file tests/fixtures/repository.json
```

Скрипт находит исходники независимо от текущей папки. Относительный путь
тестового файла считается от текущей папки пользователя.

## Настройки

| Опция | Назначение | По умолчанию |
|---|---|---|
| --package | Имя исходного пакета, обязательная опция | — |
| --version | Версия или тег исходного npm-пакета | latest |
| --url | HTTP(S)-адрес реестра | https://registry.npmjs.org |
| --test-file | Путь к JSON; включает режим тестового репозитория | — |
| --depth | Максимальное число переходов от корня, 0–100 | 3 |
| --reverse | Вывод обратных зависимостей тестового репозитория | выключен |

В тестовом режиме сеть не используется, версия и URL не влияют на данные.
Обратный поиск выполняется по всему переданному JSON-репозиторию.
Глубина 0 показывает корень, 1 — его непосредственных соседей.
Вершины на границе присутствуют, но их исходящие связи не исследуются.
Циклические связи сохраняются, повторная обработка вершин исключена.

У npm-вершин учитываются имя и версия. Диапазоны dependencies разрешаются
самостоятельно: точные версии, теги, ^, ~, x/*, сравнения, AND, OR и диапазоны
с дефисом; учитываются prerelease и npm aliases. Анализируются обычные
registry-зависимости dependencies. Правила установки peer/optional, overrides,
workspace и lock-файлы не моделируются. Ссылки git/file/URL вызывают явную
ошибку, а не заменяются latest. Пакеты не устанавливаются.

## Примеры использования

Обычный граф, цикл, общая зависимость и отдельная вершина:

```sh
./run.sh --package A --test-file tests/fixtures/repository.json --depth 3
./run.sh --package A --test-file tests/fixtures/cycle.json --depth 10
./run.sh --package A --test-file tests/fixtures/diamond.json --depth 2
./run.sh --package A --test-file tests/fixtures/isolated.json
```

Обратные зависимости тем же BFS после разворота рёбер:

```sh
./run.sh --package F --test-file tests/fixtures/repository.json --reverse --depth 1
./run.sh --package F --test-file tests/fixtures/repository.json --reverse --depth 3
./run.sh --package A --test-file tests/fixtures/cycle.json --reverse --depth 10
```

Для F на глубине 1 находятся D и E; на глубине 3 — A, B, C, D, E.
Сам исходный пакет не включается в список обратных зависимостей.
Стрелки DOT сохраняют смысл: потребитель → зависимость.

Тестовый JSON содержит все упомянутые вершины, например:

```json
{"A": ["B", "C"], "B": ["C"], "C": []}
```

Три реальных пакета и сравнение со штатным npm:
[examples/README.md](examples/README.md). Вариант №6 требует вывод текста
Graphviz; сохранять бинарные изображения программа не должна.

## Ошибки и проверки

Проверяются обязательные и пустые значения, имена, версия/тег, адрес и порт,
целая глубина и её предел, доступность и синтаксис файла, структура JSON,
неизвестные вершины, ответы реестра и наличие подходящей версии.
При сетевой ошибке — до трёх попыток по 20 секунд. Ошибка не подменяется
пустым списком. Сообщения идут в stderr. Коды: 0 — успех, 1 — ошибка данных
или сети, 2 — неверные опции.

```sh
./run.sh
./run.sh --package ''
./run.sh --package A --depth -1
./run.sh --package A --depth text
./run.sh --package A --version ''
./run.sh --package A --url wrong
./run.sh --package A --test-file missing.json
./run.sh --package B --test-file tests/fixtures/isolated.json
```

Проверки выполняются вручную командами из разделов «Примеры использования»
и «Ошибки и проверки». В tests/fixtures находятся только JSON-данные:

- repository.json — разветвлённый граф; обратный поиск F на глубине 1
  должен найти D и E, на глубине 3 — A, B, C, D, E.
- cycle.json — цикл A → B → C → A; обход должен завершиться без зацикливания.
- diamond.json — общая зависимость D для B и C; D должна быть одной вершиной.
- isolated.json — пакет A без зависимостей; DOT должен содержать вершину A.

Ошибочные команды должны выводить понятное сообщение и ненулевой код возврата.
Автоматические тестовые скрипты не используются.

Проверка стиля при установленном pycodestyle:

```sh
python3 -m pycodestyle --config=/dev/null --ignore= --max-line-length=79 src
```

## Функции

Весь код программы находится в одном файле src/main.py.

- nonempty — непустое значение; depth_value — глубина;
  validate_names — имена, версия, URL; parse_args — разбор опций.
- request_json — HTTP JSON; load_test_graph — тестовый граф;
  alias_target — npm alias. NpmRepository.__init__ создаёт кэши, resolve
  выбирает версию и вершину, dependencies получает её прямые зависимости.
- bfs_recursive обрабатывает граф по уровням с рекурсией;
  reverse_graph разворачивает связи для обратного обхода.
- generate_graphviz создаёт DOT, включая отдельные вершины.
- build_graph выбирает источник и запускает BFS; print_result выводит
  результат; main обрабатывает ошибки и возвращает код завершения.
- version_key — порядок версий; partial — частичная версия;
  format_core — строка версии; upper_bound и compatible_upper — границы;
  compare — сравнение; token_matches — одно условие; hyphen_matches —
  диапазон с дефисом; prerelease_allowed — правило prerelease;
  satisfies — проверка всего диапазона; select_version — выбор версии.

В истории отражены пять этапов работы и последующие исправления.
